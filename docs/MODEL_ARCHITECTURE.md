# Собственная генеративная модель Fontgen

## Цель

Генерировать новую согласованную гарнитуру по текстовому описанию без передачи исходных глифов модели во время inference. Открытые шрифты используются только как обучающий корпус.

## Почему текущий браузерный движок не подходит

Текущий `src/fontEngine.ts` получает готовые контуры и геометрически преобразует их. Это быстрый интерактивный прототип редактора, но не генеративная модель. Увеличение числа шрифтов или усложнение деформации не устранит это ограничение.

## Архитектура v4 (действующий fallback)

Production-конфигурация ограничена 5 млн параметров; текущий размер — 4 649 201.

V4.1 продолжает raster-only обучение v4 на авторазмеченном корпусе. Для локальных vector-only
примеров raster-цели один раз восстанавливаются непосредственно из исходных Bézier-команд с
even-odd fill; проверка пересечения с маской исходного шрифта превышает 95%. Эпохи 47–49 используют
balanced sampling по 8 192 примера и снизили новую validation-метрику 3.46524 → 3.17762 → 3.02412.

1. **Prompt encoder.** Обучаемый byte-level Transformer понимает русские и английские описания без внешнего API.
2. **Family latent + FiLM.** Один вектор стиля используется для всех символов семьи и модулирует каналы hi-res refiner через FiLM. Prompt-only auxiliary heads предсказывают категорию и типографические оси, поэтому decoder не может без штрафа игнорировать текст.
3. **Glyph content.** Unicode embedding сообщает, какой символ нужно построить, но не содержит чужого контура.
4. **Hi-res boundary decoder.** Модель строит нормализованную границу 128×128. BCE/Dice сохраняют заполнение, а Sobel edge loss отдельно выравнивает края штрихов, терминалы и засечки.
5. **Recognition head.** Отдельный classifier обязан распознать в маске запрошенный Unicode; случайный красивый силуэт не уменьшает этот loss.
6. **Vectorization.** Production inference увеличивает probability field в 4 раза, извлекает
   sub-pixel границу после topology cleanup, ограничивает длину Bézier-ручек и превращает длинные,
   горизонтальные и вертикальные участки в настоящие `L`. Контуры остаются замкнутыми `M/L/C/Z`.
7. **Typography controls.** Вес, ширина, наклон, PANOSE-контраст и PANOSE/curated-roundness входят в conditioning. После генерации наклон уточняется точным affine shear без разрыва контуров.
8. **Losses.** Raster BCE/Dice + Sobel edge alignment + entropy sharpening + glyph recognition + family category classification + prompt category/control regression + style variance. Вспомогательный command CE/coordinate Smooth L1 остается для экспериментов с прямым vector decoder.

### V4.1 SDF refinement

Совместимый SDF-апгрейд сохраняет prompt/style/glyph encoders и старые raster-веса. Raster-ветка
по-прежнему задаёт occupancy, а отдельный bounded residual уточняет signed distance field; его
нулевая изолиния становится sub-pixel контуром. Новый coordinate-aware residual refiner
инициализируется нулём, поэтому старый checkpoint до первого fine-tune воспроизводит прежний силуэт.
SDF regression получает повышенный
вес около границы, normal alignment выравнивает касательные, Eikonal stabilizes distance gradient,
curvature loss подавляет локальные волны, а 32/64/128 multi-scale supervision сохраняет крупную
анатомию и просветы. Принятый production-режим замораживает исходную V4.1 и обучает только bounded
SDF residual. На inference topology guard проверяет connected components, Euler number, площадь и
IoU; небезопасная коррекция отклоняется отдельно для каждого глифа. Полное обновление raster decoder
отклонено после specimen-gate: validation снижалась, но появлялись разрывы штрихов и закрытые просветы.

## Архитектура v5 (следующий качественный этап)

Ограничение 5 млн снято. V5 существует параллельно с v4 и не подменяет рабочий API до
визуальной приёмки checkpoint.

1. **Semantic prompt encoder.** Замороженный локальный multilingual MiniLM (около 0.1B,
   Apache-2.0) кодирует свободные русские и английские промпты в 384 измерения. Во время обучения
   embeddings кешируются; внешнего API нет.
2. **Vector decoder.** Отдельный Transformer на 22 455 966 обучаемых параметров напрямую
   предсказывает последовательность `M/L/Q/C/Z` и контрольные точки. Исходный шрифт на inference
   не подаётся.
3. **Self-refinement.** После причинного построения второй non-causal Transformer видит весь
   контур и исправляет стыки, повторные точки и дальние зависимости внутри глифа.
4. **Vector losses.** Command CE, masked coordinate Smooth L1 и геометрический loss по
   дискретизированным line/quadratic/cubic сегментам обучают непосредственно кривые. Растеризация
   отсутствует и на выходе, и в основном пути loss.
5. **Prompt grounding.** Категория гарнитуры предсказывается из prompt embedding как
   вспомогательная задача, но не передаётся decoder готовой меткой. Это не даёт модели обходить
   смысл пользовательского текста.
6. **Typography grounding.** Авторазметка измеряет mean width, x-height/cap-height, descender,
   curve ratio, сложность и число контуров. Отдельная regression head восстанавливает эти признаки
   из prompt/control latent и напрямую штрафует игнорирование описаний формы.
7. **Оценка.** Семейства целиком разделены между train и validation (436/60 для расширенного
   корпуса при доле 12%).
   Smoke и probe checkpoint служат только проверке pipeline и никогда не подключаются к UI.

V5 сейчас оставлен как экспериментальная ветка. Действующий локальный путь — V4.1 с улучшенной
семантической нормализацией промпта и sub-pixel очисткой векторных контуров.

## Structured quadratic v1

Эта ветка заменяет прямой autoregressive coordinate decoder на явную иерархию:

1. multilingual prompt и controls кодируются в единый family latent для всей гарнитуры;
2. отдельный causal structure decoder генерирует только топологию `M/L/Q/Z`;
3. geometry decoder получает полную структуру и параллельно предсказывает quadratic control/end
   points, поэтому ошибка координат не накапливается от предыдущего сегмента;
4. non-causal vector refiner видит весь глиф и вносит ограниченную residual-поправку;
5. sampled-curve, curvature и axis-alignment losses отдельно контролируют гладкость кривых и
   точность горизонтальных/вертикальных линий.
6. frozen V4.1 teacher передаёт student-модели только prompt/style embedding и распределение
   категорий; raster decoder и дефектные старые контуры в distillation targets не входят.

Корпус полностью канонизирован в quadratic-v1 с погрешностью cubic→quadratic не более 0.001 em:
97 347 глифов, 935 965 линий и 1 423 158 quadratic-сегментов, без raster-полей. Structured model
содержит 25 118 353 обучаемых параметра. Его обучение приостановлено; эта ветка не заменяет
действующий локальный V4.1 checkpoint.

## Данные

- только лицензии, разрешающие обучение и производные результаты; происхождение каждого файла хранится в manifest;
- нормализация в 1000 UPM, декомпозиция компонентов и единый формат контурных команд;
- базовый Google Fonts корпус: 216 OFL-семейств, 346 лиц, 39 130 глифов и 147 символов;
- расширенный v5-корпус после дедупликации: 496 семейств, 767 начертаний и 97 347 глифов;
- 58 217 уникальных примеров получены из локальной библиотеки легально приобретённых шрифтов,
  исключая `Trial`/`Demo`; бинарники не копируются в репозиторий, provenance хранится в manifest;
- sqrt-balanced sampling не позволяет преобладающим гротескам вытеснить антикву, display,
  handwriting и monospace во время обучения;
- авторазметка создаёт 10 групп тегов и 10 103 уникальных естественных промпта вместо прежних 464;
- 121 курсивное лицо и 2 289 явно округлых примеров;
- train/validation делятся по семьям (194/22), а не по отдельным глифам;
- параметры для автоматических подписей извлекаются из OS/2 и геометрических измерений; затем нужен вручную проверенный набор естественных русских/английских описаний;
- первый charset: Basic Latin, русская кириллица, цифры и основная пунктуация.

## Развёртывание

GitHub Pages обслуживает React-интерфейс. Отдельный GPU API загружает чекпойнт, создаёт job и возвращает массив новых контуров. Интерфейс собирает их в SVG/TTF/OTF. Ключ YoFont не нужен.

## Этапы

1. v0 — raster + outline multi-task модель и smoke-check на малом корпусе.
2. v0.2 — полноценный OFL-корпус, family split, topology-aware vectorization.
3. v0.5 — differentiable raster loss и улучшение визуальной гладкости.
4. v1 — contrastive prompt/style alignment, несколько связанных начертаний и production inference API.
